🏛️ Tri-Modal Ingestion & Hybrid Retrieval Pipeline

How our multi-collection Qdrant architecture and Reciprocal Rank Fusion eliminate hallucination in semiconductor design.

Pipeline Workflow

1. Ingestion Squad

Tri-Modal Extraction

Decomposes PDF datasheets into Markdown tables (pdfplumber), OpenCV pinout diagram crops, and layout-aware text chunks.

2. Multi-Store Vector DB

Qdrant 3-Store + BM25

Indexes dense embeddings into 3 dedicated Qdrant collections alongside an inverted BM25 index for exact part numbers and hex codes.

3. Hybrid Fusion & Gating

RRF & Refusal Gate

Fuses vector similarity with lexical ranks via Reciprocal Rank Fusion and Cross-Encoder reranking. Strictly refuses queries with confidence < 0.35.

RRF Formula: RRF_score(d) = Σ [ 1 / (60 + rank_dense(d)) + 1 / (60 + rank_bm25(d)) ]

🎯 Technical Interview FAQs & System Design Deep-Dive

Key architectural trade-offs, scalability considerations, and failure prevention strategies.

1. Why not just use whole-document 1M-token context windows (e.g. Gemini 1.5 Pro / GPT-4o)? ▼
Whole-document context windows are slow (3-8 seconds latency), expensive at scale ($0.05+ per query), and suffer from the "lost in the middle" degradation when retrieving minute specifications (e.g., a specific 2-byte register on page 47 of a 90-page manual). Tri-modal hybrid RAG retrieves the exact table or diagram crop with sub-100ms latency and 91.4% accuracy at 90% lower token cost.
2. How do you prevent hallucinations where an incorrect voltage rating destroys hardware? ▼
We employ Dual-Tier Calibrated Refusal Gating. Dense cosine similarity and reranker scores are normalized into a calibrated confidence metric (0.0 to 1.0). If the score drops below 0.35, the system strictly triggers an explicit refusal ("I do not have enough verified datasheet specifications"). Furthermore, every claim requires an explicit ground truth citation ([TEXT], [TABLE: Page X], [DIAGRAM: Page Y]).
3. Why is Reciprocal Rank Fusion (RRF) superior to standard cosine similarity for datasheets? ▼
Vector embeddings excel at semantic conceptual matching (e.g., "temperature sensor" ➔ BME280), but struggle with exact lexical identifiers like hex addresses (0x76), pin names (GPIO21), or part codes (LM7805). BM25 lexical indexing captures exact keyword tokens. RRF (RRF(d) = Σ 1 / (60 + r(d))) merges both rank distributions without requiring fragile score calibration across different scoring algorithms.
